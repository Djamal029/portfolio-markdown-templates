Conseils avant de publier

Un portfolio sert à prouver ce que vous savez faire.

Mettez tous vos projets data sur GitHub

Projets de cours, projets personnels, analyses, tableaux de bord : chacun peut devenir un dépôt public.

  • C'est une preuve. Un recruteur lit votre code, vos notebooks et vos résultats au lieu de vous croire sur parole.
  • Ça montre votre façon de travailler : code propre, historique Git, tests, documentation. C'est souvent ce qui départage deux profils.
  • Le README fait vitrine : contexte, données, méthode, résultats et une image. Cinq minutes de lecture suffisent pour comprendre le projet.
  • Vos projets se relient au portfolio : dans chaque fichier projet, la ligne repo: ajoute un bouton « Code ».
  • Épinglez vos 4 à 6 meilleurs dépôts sur votre profil GitHub pour qu'on les voie en premier.

Pas encore de projet sur GitHub ? Ne mettez pas le lien

Un bouton GitHub qui mène à un profil vide fait plus de mal que pas de bouton du tout.

  • Un profil vide envoie un mauvais signal : le recruteur clique, ne trouve rien, et se demande si les projets du portfolio existent vraiment.
  • Laissez simplement la ligne vide dans content/profile.md : github: "". Le modèle masque alors tous les boutons GitHub.
  • Ajoutez le lien plus tard, dès que vous avez deux ou trois dépôts propres avec un vrai README.
  • Même règle pour les liens « Code » des projets : n'en mettez que s'ils pointent vers un dépôt public et lisible.

Choisissez votre modèle dans site.yml

Ouvrez content/site.yml. Mettez la lettre du modèle choisi, la langue, et si vous voulez une palette ou vos couleurs. Laissez vide ce que vous ne voulez pas changer.

Étape 4 sur 10 · Profil

Remplissez votre profil

Dans content/profile.md : nom, titre, ville, e-mail, liens. Sous les trois tirets, deux phrases : ce que vous faites et ce que vous cherchez. Pas de profil GitHub rempli ? Laissez github: "".

Étape 5 sur 10 · Photo

Ajoutez votre photo

Une photo carrée, nette, visage bien éclairé, fond simple. Copiez-la dans content/images/, puis écrivez son nom dans profile.md. Le texte photo_alt décrit l'image pour les lecteurs d'écran.

content/images/

└─ thumbnails/

Votre photo apparaîten haut de toutes les pages
Étape 6 sur 10 · Expériences

Une expérience = un fichier

Copiez un fichier d'exemple de content/experiences/ et renommez-le. En haut : poste, structure, dates. En dessous : 2 ou 3 puces qui commencent par un verbe d'action et donnent un résultat chiffré.

experiences/stage-2025.md
title: Stagiaire data scientistorganisation: Nom de l'entreprisestart: 2025-06 end: 2025-08type: internship---- Construit un modèle qui a fait passer le rappel : 0,58 → 0,74.- Réduit le reporting : 2 j → 2 h.
Étape 7 sur 10 · Projets

Décrivez un projet comme une histoire courte

Un fichier par projet dans content/projects/. Un titre clair (une question marche très bien), un résumé d'une phrase, des étiquettes, et le lien vers le code. Dans le corps : Contexte, Données, Méthode, Résultats, Ce que j'ai appris.

projects/velos.md
title: Où manquera-t-il des vélos demain ?summary: Prévoir les stations vides.tags: [Python, Séries temporelles]featured: true # mis en avantlinks: repo: https://github.com/...

Étape 8 sur 10 · Miniatures

Trouvez des miniatures libres de droits

Prenez des images que vous avez le droit d'utiliser : Unsplash, Pexels, Pixabay, Wikimedia Commons, ou mieux, une capture de votre propre graphique. Sur Google Images, filtrez par « Licences Creative Commons ». Pinterest sert à trouver des idées, pas des images : elles appartiennent à leurs auteurs.

Étape 9 sur 10 · Vérifier

Regardez le résultat avant de publier

Windows : double-clic sur install.cmd. Mac ou Linux : sh install.sh. Le site s'ouvre dans le navigateur. S'il y a une erreur, le message donne le fichier et la ligne à corriger.

terminal
$ sh install.sh previewLecture de content/ ... okSite généré : 6 pages dans docs/Ouvert sur http://localhost:8000Erreur : velos.md, ligne 4 (date AAAA-MM)
Étape 10 sur 10 · Publier

Envoyez, et votre site est en ligne

Une seule fois : sur GitHub, Settings > Pages > Source : GitHub Actions. Ensuite, à chaque envoi (commit puis push, ou « Push origin » dans GitHub Desktop), le site se met à jour tout seul en une minute.

terminal
$ git add .$ git commit -m "Mon portfolio"$ git pushGitHub Actions : site publié ✓
votre-compte.github.io/portfolio
Lire les dix étapes en texte
  1. Copier le modèle. Sur la page GitHub du projet, « Use this template » puis « Create a new repository ». Nom court (portfolio), dépôt public. Si vous l'appelez votre-compte.github.io, l'adresse sera la plus courte possible.
  2. Le récupérer. git clone https://github.com/votre-compte/portfolio, ou GitHub Desktop (File > Clone repository), ou « Code > Download ZIP ». Ouvrez le dossier dans VS Code.
  3. Choisir le modèle. Dans content/site.yml : template: (une lettre), language: fr ou en, et si vous voulez palette: ou vos couleurs.
  4. Le profil. content/profile.md : nom, titre, ville, e-mail, LinkedIn. Sous les trois tirets, deux phrases (ce que vous faites, ce que vous cherchez). Profil GitHub vide : laissez github: "".
  5. La photo. Carrée (environ 800×800 px), nette, bien éclairée, fond simple. Copiez-la dans content/images/ et écrivez photo: images/photo.jpg et une courte description dans photo_alt.
  6. Les expériences. Un fichier par expérience dans content/experiences/ : title, organisation, start, end (ou present), type. Dessous, 2 ou 3 puces : un verbe d'action et un résultat chiffré.
  7. Les projets. Un fichier par projet dans content/projects/ : titre clair (une question fonctionne bien), summary d'une phrase, tags, featured: true pour vos meilleurs, links: repo: vers le code. Dans le corps : Contexte, Données, Méthode, Résultats, Ce que j'ai appris.
  8. Les miniatures. Images libres de droits : Unsplash, Pexels, Pixabay, Wikimedia Commons (vérifiez la licence de chaque fichier), ou une capture de votre propre graphique, souvent le meilleur choix. Google Images : outil « Droits d'usage », « Licences Creative Commons ». Pinterest : pour l'inspiration seulement. Format 16:9 (environ 1200×675 px), dans content/images/thumbnails/, puis thumbnail: et thumbnail_alt: dans le fichier du projet.
  9. Vérifier. install.cmd (Windows) ou sh install.sh preview (Mac, Linux) : le site s'ouvre dans le navigateur. Une erreur indique le fichier et la ligne.
  10. Publier. Une fois : Settings > Pages > Source : GitHub Actions. Ensuite chaque git push (ou « Push origin » dans GitHub Desktop) met le site à jour en une minute environ.
